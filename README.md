# typikon

Typikon readings on each day.

## Раздел «Правило»

В меню рядом с помянником: правило дня, Псалтирь (кафизмы, подряд,
поминальное чтение), подготовка к Причащению и служба дня.

Служба дня (`/ordo`) использует `GET /api/v2/ordo/services` с датой,
`lang=cu`, `psalms=1`. Это существующая JSON-проекция дневного `.ordo`:
сервер сшивает тела пакета с шагами. `/ordo/package` в текущем публичном
контракте возвращает ZIP одной службы и требует `service`; параметра
линейной подачи нет. Приложение показывает места и тексты по порядку,
без ролей и тетрадей, сохраняя вложенные тексты и повторы. Отсутствующие
в пакете тексты обозначаются явно, в том числе внешние ссылки на Писание.

Служба дня кэшируется обычным HTTP-кэшем приложения. Предзагрузка следует
настройке «скачивать чтения заранее» и запускается вместе с текстами
показанного на главной дня. Отказ ordo не объявляет общий API-ключ негодным;
при 401/403 экран предлагает обновление приложения.

Напоминания правила доступны на экране правила и в настройках. Ключи
`rule_remind_morning` / `rule_remind_evening` хранятся непосредственно в
SharedPreferences: фоновому изоляту Redux не нужен. Утреннее окно 7–9,
вечернее 21–23; фактическое пробуждение определяет ОС.

Проверки: `flutter test`; `flutter analyze --no-fatal-infos` (в проекте
есть прежние замечания уровня info). Новые сценарии службы дня,
предзагрузки и продолжения чтения — `test/ordo_services_test.dart`,
опись меню — `test/menu_routes_test.dart`.

Перед выпуском нужно проверить доступ сборочного ключа к разделу ordo
(выпуск/расширение ключа — операция владельца), чтение на устройстве и
открытие предзагруженной службы без сети. Само наличие локальных тестов
не подтверждает доступ ключа на сервере.
